# Security Policy

## Supported versions

Security fixes are expected to land on the current development line first and then
reach the next public release.

## Reporting a vulnerability

Please do not post exploit details in a public issue or discussion.

Preferred path:

- Use GitHub Private Vulnerability Reporting for this repository when it is enabled.

If private reporting is not yet available:

- Open a minimal GitHub issue or discussion asking for a private contact route.
- Do not include proof-of-concept exploits, credentials, or sensitive details in that public post.

## What to include

Helpful reports usually include:

- A short description of the issue.
- Affected versions or commits, if known.
- Reproduction steps.
- Impact and any suggested mitigation.
