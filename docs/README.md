# Dogu technical documentation

English is the primary language for technical documentation because it is the
most practical default for tooling, packaging, external contributors and future
GitHub workflows. When a document describes user-facing project decisions or
release operations, include a Spanish section as well.

## Current documents

| Document | Purpose | Language policy |
| --- | --- | --- |
| [building.md](building.md) | Local development, builds, updater keys and CI release flow. | English first, Spanish summary. |
| [release-channels.md](release-channels.md) | Stable/Beta policy, updater support matrix and release checklist. | English first, Spanish section. |
| [updater-signing.md](updater-signing.md) | Official updater signing keys, GitHub Secrets and rotation rules. | English first, Spanish section. |
| [chdman.md](chdman.md) | chdman source, support and integration decisions. | English first, Spanish section. |
| [ghost-files.md](ghost-files.md) | Queue ghost-file architecture and manual test checklist. | English technical reference. |

Repository-level community/legal files such as `CONTRIBUTING.md`,
`CODE_OF_CONDUCT.md` and `SECURITY.md` may stay in English unless a Spanish copy
is specifically needed.

## Español

El inglés es el idioma principal para documentación técnica porque facilita
herramientas, empaquetado, colaboración externa y mantenimiento en GitHub. Cuando
un documento explique decisiones visibles para usuarios o procesos de release,
añadimos también sección en español.

Los documentos técnicos principales están en esta carpeta. El README general y
el changelog se mantienen bilingües.
